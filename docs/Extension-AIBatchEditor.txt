{{Warning|boxcolor=orange}}
This extension sends page wikitext to an external large-language-model (LLM) API configured by the wiki administrator. Review your provider's privacy policy, data-retention rules, and applicable laws before enabling it on a production wiki. API keys must be stored server-side only (for example in environment variables), never in client-side code or version control.
{{Warning}}

The '''AIBatchEditor''' extension provides [[Special:AIBatchEditor|Special:AIBatchEditor]], a Codex-based batch editor for MediaWiki 1.43+. Select many pages at once (by title list, category, or template transclusion), run AI-assisted operations on them, preview each proposed change as a wikitext diff, and save only the edits you approve.

Saved edits go through MediaWiki's normal edit pipeline: they are attributed to the saving user, appear in page history, can be reverted, and are tagged with the <code>aibatcheditor</code> [[Manual:Tags|change tag]].

'''User guide:''' [[Help:Extension:AIBatchEditor]]

== Features ==

* Validate pages from a title list, from [[Help:Categories|category]] members, or by template transclusion (with optional title-prefix filter).
* Built-in AI operations: wikilinks, spellcheck, formatting, writing style, templates (with remote reference fetch), and custom (instructions-only).
* Three aggressiveness profiles per operation: conservative, balanced, aggressive (configurable via <code>$wgAIBatchEditorOperationProfiles</code>).
* Strict instruction-compliance prompts and low default temperature (<code>$wgAIBatchEditorTemperature</code>).
* Optional batch-wide and per-page AI instructions.
* Temporary prompt preview in the UI and API (<code>$wgAIBatchEditorPromptPreview</code>).
* '''Server-side batch processing''' — the browser starts a batch, calls <code>aibatcheditorbatchadvance</code> for LLM work, and polls <code>aibatcheditorbatchstatus</code> for progress; each advance request processes up to <code>$wgAIBatchEditorConcurrency</code> pages.
* Per-page diff preview (lazy-loaded), '''Preview article''' (rendered proposed page in a new tab), re-draft, and selective approval before save.
* Retry failed pages without re-running the whole batch.
* Cancel a running batch — stop remaining pages while keeping finished results.
* Proposal warnings for risky AI output (major deletions, near-empty text, large growth, removed headings).
* Draft tokens — HMAC tokens bind each proposed edit to the user, base revision, and proposed text hash; saves reject stale or tampered proposals.
* Diff-reviewed and warning confirmations before bulk approve or save.
* Post-save revision and history links in the results panel.
* Page size limits, per-user hourly rate limits, and structured server-side logging.
* Seven [[API:Main page|Action API]] modules for list, preview, batch start/status/cancel, diff, and save workflows.

== Requirements ==

* MediaWiki &gt;= 1.43.0
* PHP 8.1+ (required by MediaWiki 1.43; OpenSSL extension enabled)
* A Grok-compatible chat-completions HTTP API (xAI Grok by default; other OpenAI-style endpoints may work if configured)
* JavaScript enabled in the browser
* Outbound HTTPS from the wiki server to the LLM endpoint (and to allowed remote wikis for the <code>templates</code> operation)
* Users need the <code>aibatchedit</code> user right (granted to <code>sysop</code> by default)

== Compatibility ==

The only formal dependency declared in <code>extension.json</code> is '''MediaWiki &gt;= 1.43.0'''. The special-page UI uses core '''Vue''' (<code>createMwApp</code>) and '''Codex''' (<code>CodexModule</code>), which are not available on MediaWiki 1.42 or older. The extension has been tested on MediaWiki '''1.43 LTS through 1.45+'''.

=== Operational prerequisites ===

# <code>$wgAIBatchEditorApiUrl</code> configured and API key available server-side (for example <code>XAI_API_KEY</code> in <code>$IP/.env</code>, loaded automatically).
# Users need the <code>aibatchedit</code> right (granted to <code>sysop</code> by default).
# Users still need normal <code>edit</code> permission on each page they save.
# For <code>templates</code>: server outbound HTTPS to hosts in <code>$wgAIBatchEditorTemplateSourceAllowHosts</code>.

=== Page and content limits ===

Only pages that meet '''all''' of the following are processed:

* Exist and are '''not redirects'''
* Main content model is '''wikitext''' (not JSON, CSS, or other models)
* User can '''read''' and '''edit''' the page
* Category batch lists: '''content namespaces''' only
* Wikitext size within <code>$wgAIBatchEditorMaxPageSize</code> (default 2097152 bytes / 2 MiB; <code>0</code> = no limit)

Does '''not''' apply to typical non-wikitext system pages, file description pages using other models, or pages the user cannot edit.

== Installation ==

# Download or clone the extension from [https://github.com/urimacias/AIBatchEditor GitHub] into your wiki's <code>extensions/</code> directory:

<syntaxhighlight lang="bash">
cd extensions/
git clone https://github.com/urimacias/AIBatchEditor.git AIBatchEditor
</syntaxhighlight>

# Add the following to the bottom of your [[Manual:LocalSettings.php|LocalSettings.php]]:

<syntaxhighlight lang="php">
wfLoadExtension( 'AIBatchEditor' );

$wgAIBatchEditorApiUrl = 'https://api.x.ai/v1/chat/completions';
// XAI_API_KEY in $IP/.env — loaded automatically; do not commit the key
</syntaxhighlight>

Sensible defaults are built into the extension (model <code>grok-4.3</code>, 300 s LLM timeout, batch cap 25, 60 requests/hour, concurrency 1). Override only when needed. Wiki-specific LLM policy belongs in <code>$wgAIBatchEditorSystemPromptAppend</code>.

Store the API key in the environment (for example <code>XAI_API_KEY</code> in <code>$IP/.env</code> or Docker <code>.env</code>), not in git.

# Visit [[Special:Version]] and confirm '''AIBatchEditor''' appears.
# Open [[Special:AIBatchEditor]] with a user who has the <code>aibatchedit</code> right.

=== Shared hosting / cPanel ===

On '''cPanel''' or other '''PHP-FPM''' hosts without memcached, enable a persistent object cache in <code>LocalSettings.php</code>:

<syntaxhighlight lang="php">
$wgMainCacheType = CACHE_DB;  // uses the objectcache table (e.g. mw_objectcache)
</syntaxhighlight>

Without this, '''Redactar / Draft''' fails immediately with API error <code>batch-not-found</code> because batch progress is stored in MediaWiki object cache and the default per-request memory cache is not shared between HTTP workers. See [[#Troubleshooting]].

=== LLM system prompt ===

The server builds a structured system message for every AI request (prompt version '''4''' in <code>PromptFactory</code>):

# '''ROLE''' — MediaWiki wikitext editor and wiki content language code
# '''OUTPUT CONTRACT''' — full wikitext only; minimal edit; fidelity (no fact/markup drift); no invention; return input unchanged when already satisfied
# '''TASK — Operation''' — one-line goal (what kind of edit)
# '''TASK — Profile''' — intensity only (how much to change within scope); <code>$wgAIBatchEditorOperationProfiles</code> supplies UI help and LLM text
# '''SCOPE''' — what may change per operation (boundaries, not intensity)
# '''INSTRUCTIONS''' — optional editor focus text; supplementary to the operation task
# '''Template references''' — fetched wikitext when using the <code>templates</code> operation
# '''WIKI-SPECIFIC RULES''' — optional bullets from <code>$wgAIBatchEditorSystemPromptAppend</code>

The '''Custom''' operation hides the profile dropdown in the UI and always uses '''balanced''' intensity.

The user message contains only <code>=== INPUT ===</code> and the page wikitext.

'''North star:''' make the smallest change that completes the task; copy everything else exactly; invent nothing.

Precedence (highest first): '''operation task + scope''' → '''editor instructions''' (additional focus only) → '''template references''' → '''wiki-specific rules''' (<code>SystemPromptAppend</code>) → built-in contract defaults in <code>PromptFactory</code>.

Process logs include <code>promptVersion</code> for audit trails.

==== Wiki-wide append ====

Administrators can set <code>$wgAIBatchEditorSystemPromptAppend</code> to an array of strings. Each non-empty string becomes a bullet under '''WIKI-SPECIFIC RULES'''. Built-in output contract and scope rules always remain; this setting cannot remove or replace them.

Use <code>$wgAIBatchEditorPromptPreview = true</code> and '''Preview prompt''' on [[Special:AIBatchEditor]] to inspect the composed prompt while tuning.

<syntaxhighlight lang="php">
$wgAIBatchEditorSystemPromptAppend = [
    'This wiki documents family history; never invent names or dates.',
    'Prefer [[Plantilla:Persona]] for biography pages.',
];
</syntaxhighlight>

Example: disable the aggressive style operation and lower the batch cap further:

<syntaxhighlight lang="php">
$wgAIBatchEditorMaxBatch = 15;
$wgAIBatchEditorEnabledOperations = [
    'wikilinks' => true,
    'spellcheck' => true,
    'formatting' => true,
    'style' => false,
    'templates' => true,
    'custom' => true,
];
$wgAIBatchEditorTemperature = 0.1;
// $wgAIBatchEditorPromptPreview = true; // optional: show prompt debug UI while testing
</syntaxhighlight>

== AI capabilities and limits ==

The extension is a '''wikitext batch editor''', not a research agent. For each page, the server sends the current wikitext, your instructions, and (for the <code>templates</code> operation) reference template definitions fetched from allowed remote wikis. The model returns revised wikitext only.

'''The AI can:'''

* Edit wikitext (links, spelling, structure, tone, template transclusions)
* Follow batch-wide or per-page instructions
* Insert, upgrade, or clone templates when you name references (for example <code>Plantilla:Ficha</code> from es.wikipedia.org)

'''The AI cannot:'''

* Search the web or call external APIs (weather, news, geocoding, and so on)
* Read other pages on your local wiki as context
* Share context between pages in a batch (each LLM request is isolated)
* Edit non-wikitext content models or process redirects and missing pages

If factual data is required (for example historical weather on a wedding date), '''provide it in the instructions''' or in the wikitext. Otherwise the model may invent plausible-sounding but unverified text.

Prompts use a surgical-edit system message (minimal change, fidelity, no invention) and a default low temperature to improve literal instruction following.

== API modules ==

All modules require the <code>aibatchedit</code> right.

{| class="wikitable"
! Module !! Mode !! Purpose
|-
| <code>aibatcheditorlist</code> || read || Validate and list pages for batch editing; returns rate-limit status.
|-
| <code>aibatcheditorpreview</code> || read || Build LLM prompts for one page without calling the AI or consuming rate limit.
|-
| <code>aibatcheditorbatchstart</code> || read || Start a server-side batch run; returns <code>batchId</code>.
|-
| <code>aibatcheditorbatchadvance</code> || read || Process the next chunk of a batch (LLM work; may be long-running).
|-
| <code>aibatcheditorbatchstatus</code> || read || Read batch progress from object cache (fast; no LLM calls).
|-
| <code>aibatcheditorbatchcancel</code> || read || Cancel a running batch; clears pending pages.
|-
| <code>aibatcheditordiff</code> || read || Render a wikitext diff for preview.
|-
| <code>aibatcheditorarticlepreview</code> || read || Stage proposed wikitext and return a URL to render it as an article preview.
|-
| <code>aibatcheditorrefreshdrafttokens</code> || write || Refresh <code>draftToken</code> values before save (CSRF; <code>edits</code> without <code>draftToken</code>).
|-
| <code>aibatcheditorsave</code> || write || Save approved proposed edits (CSRF token and <code>draftToken</code> per edit required).
|}

The browser UI uses '''batch start''', then '''batchadvance''' (sequential LLM work) with '''batchstatus''' polling for progress. Each changed page in batch responses includes <code>draftToken</code> and optional <code>warnings</code>.

'''batchstatus''' responses are lightweight (progress only; no wikitext bodies). Full page results and <code>draftToken</code> come from '''batchadvance'''. '''aibatcheditorsave''' recovers stale tokens when the revision still matches; '''aibatcheditorrefreshdrafttokens''' re-issues tokens explicitly for API integrations.

Shared list parameters:

* <code>titles</code> — pipe- or newline-separated page titles
* <code>category</code> — category name without the <code>Category:</code> prefix
* <code>template</code> — template name (with or without the <code>Template:</code> prefix or braces); lists pages that transclude it on this wiki
* <code>prefix</code> — optional title-prefix filter for category or template members

Batch-specific parameters:

* <code>operation</code> — <code>wikilinks</code>, <code>spellcheck</code>, <code>formatting</code>, <code>style</code>, <code>templates</code>, or <code>custom</code>
* <code>profile</code> — <code>conservative</code>, <code>balanced</code>, or <code>aggressive</code> (default: <code>balanced</code>)
* <code>instructions</code> — optional custom directions sent to the LLM (required for <code>custom</code>)
* <code>templates</code> — pipe- or newline-separated template names (required for <code>templates</code>; max 5 per request)
* <code>templatesource</code> — optional HTTPS wiki base URL override (must be in <code>$wgAIBatchEditorTemplateSourceAllowHosts</code>)
* <code>summary</code> — optional edit summary echoed in the API response (used by the UI when saving)

Batch start returns <code>batchId</code>. The UI calls <code>aibatcheditorbatchadvance</code> to process pages (LLM work) and polls <code>aibatcheditorbatchstatus</code> for fast read-only progress.

When <code>$wgAIBatchEditorPromptPreview</code> is enabled, batch status responses include <code>promptSystem</code> and <code>promptUser</code> per page.

Preview-specific parameters (<code>aibatcheditorpreview</code>):

* <code>titles</code> — single page title (required)
* <code>pageinstructions</code> — optional per-page instructions override for preview only

Save parameters:

* <code>summary</code> — edit summary applied to each saved page (required)
* <code>edits</code> — JSON array of objects with <code>title</code>, <code>revid</code>, <code>proposed</code> wikitext, and <code>draftToken</code>

See [[Special:ApiHelp]] on your wiki for generated documentation and examples.

== Logging and change tags ==

* Batch actions are logged to the <code>aibatcheditor</code> [[Manual:Structured logging|Monolog channel]] (list, process, save). Process logs include <code>promptVersion</code> (currently <code>3</code>). Configure your wiki logging to retain this channel for audit trails.
* Saved revisions are tagged <code>aibatcheditor</code> ("AI Batch Editor").

== Security notes ==

* LLM requests are made server-side only; wikitext is not sent to the model until a privileged user runs a batch.
* The API key is read from wiki configuration and is never passed to the browser.
* Save requests use MediaWiki's standard CSRF protection.
* Saves require a valid <code>draftToken</code> matching the user, base revision, and proposed text.
* Saves check the base revision ID and fail with an edit-conflict error if the page changed meanwhile.
* Per-user hourly rate limiting reduces accidental or abusive LLM usage.
* Remote template fetches use HTTPS only and an administrator-defined host allowlist (SSRF protection).
* Template and page size caps limit prompt injection and oversized LLM payloads.
* Batch state is stored in object cache and tied to the starting user.

== Troubleshooting ==

=== Redactar fails with <code>batch-not-found</code> ===

'''Symptom:''' Clicking '''Redactar''' (Draft) fails immediately. The UI may show <code>batch-not-found</code> or an untranslated <code>⧼batch-not-found⧽</code>.

'''Cause:''' Server-side batch runs store progress in MediaWiki '''object cache''' (<code>BatchRunService</code>). The browser calls <code>aibatcheditorbatchstart</code>, then polls <code>aibatcheditorbatchstatus</code> about every 2.5&nbsp;s (<code>$wgAIBatchEditorPollIntervalMs</code>). On cPanel / PHP-FPM without memcached, the default cache is '''per-request memory''' — start and status requests often hit different PHP workers, so the batch ID is not found.

'''Fix:''' Enable a persistent object cache in <code>LocalSettings.php</code>:

<syntaxhighlight lang="php">
$wgMainCacheType = CACHE_DB;   // uses objectcache table; no memcached required
</syntaxhighlight>

Alternatives: <code>CACHE_MEMCACHED</code> with <code>$wgMemCachedServers</code>, or Redis if available.

'''Verify:''' The <code>objectcache</code> table exists (for example <code>mw_objectcache</code>). After enabling <code>CACHE_DB</code>, Redactar should show progress instead of failing instantly.

=== Batch fails with <code>http</code> or <code>⧼http⧽</code> ===

'''Symptom:''' A batch run (especially large ones) stops with an error icon and <code>http</code>, <code>⧼http⧽</code>, or a message like “The request to the wiki server failed.”

'''Cause:''' Each <code>aibatcheditorbatchadvance</code> request processes up to <code>$wgAIBatchEditorConcurrency</code> pages synchronously, and each page can take up to <code>$wgAIBatchEditorRequestTimeout</code> seconds (default 300) for the LLM call. If PHP-FPM, nginx, or the browser times out before that request finishes, the client reports a transport <code>http</code> error. Status polls are read-only and should remain fast.

'''Fix:''' Default concurrency is already 1. Raise timeouts only if needed:

<syntaxhighlight lang="php">
# Default is 300 s; raise only if grok-4.x still times out on very large pages:
# $wgAIBatchEditorRequestTimeout = 420;
</syntaxhighlight>

Also raise PHP <code>max_execution_time</code> and reverse-proxy read timeouts above the LLM timeout.

==== AI request fails with HTTP 0 on large pages ====

If only large pages fail with '''HTTP 0''' (or the timeout message), the LLM call exceeded <code>$wgAIBatchEditorRequestTimeout</code>. For <code>grok-4.3</code> on full wikitext, use at least <code>300</code> seconds (5 minutes). Check <code>aibatcheditor.log</code> for <code>llmError</code> and duration near the limit.

'''Verify:''' Single-page Redactar completes without error; a full batch advances steadily when concurrency is 1.

=== Batch runs forever with status polls but no LLM response ===

'''Symptom:''' Hundreds of small <code>aibatcheditorbatchstatus</code> requests over many minutes; few <code>aibatcheditorbatchadvance</code> calls; no AI results.

'''Cause:''' Only <code>batchadvance</code> invokes the LLM; <code>batchstatus</code> is read-only progress. A fixed client bug (<code>4474d2a</code>) had stopped the advance chain after the first page while polling continued.

'''Fix:''' Deploy the latest extension and hard-refresh the special page. Status responses omit wikitext bodies; the client schedules the next advance only after the previous advance finishes.

=== Save fails with draft-token bad signature ===

'''Symptom:''' <code>draft-token-bad-signature</code> or Spanish “la firma del token de borrador no es válida” after approve.

'''Fix:''' <code>aibatcheditorsave</code> recovers when the base revision is unchanged. Optional: <code>$wgAIBatchEditorDraftTokenSecret = $wgSecretKey;</code>. Enable <code>$wgDebugLogGroups['aibatcheditor']</code> and look for <code>draftTokenVerifyFailure</code> with <code>recovered: true</code>.

== Testing ==

From the MediaWiki root (with dev dependencies installed via <code>composer install --dev</code>):

<syntaxhighlight lang="bash">
chmod +x extensions/AIBatchEditor/tests/run-phpunit.sh
./extensions/AIBatchEditor/tests/run-phpunit.sh
</syntaxhighlight>

Expected: '''127 PHPUnit tests''' (62 unit + 65 integration).

E2E browser tests (Playwright) require Node.js, a running wiki, and a sysop account:

<syntaxhighlight lang="bash">
export MW_E2E_USER=Admin
export MW_E2E_PASSWORD='your-sysop-password'
export AIBATCHEDITOR_E2E_STUB=1
./extensions/AIBatchEditor/tests/run-e2e.sh
</syntaxhighlight>

Set <code>$wgAIBatchEditorStubMode = getenv( 'AIBATCHEDITOR_E2E_STUB' ) === '1';</code> in <code>LocalSettings.php</code> when running browser tests.

The repository also includes a manual QA checklist at <code>tests/QA-CHECKLIST.md</code>.
